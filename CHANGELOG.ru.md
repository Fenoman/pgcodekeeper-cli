## [15.3.0-neo1] - 2026-08-31

### Добавлено

- Добавлен режим `--mode BATCH` с параметром `--batch-manifest`: один JSON-файл
  описывает общие для всех выходов аргументы и сами выходы, а запуск загружает
  проект и базу один раз и пишет все скрипты миграции из одного загруженного
  сравнения. Каждый скрипт побайтно совпадает с отдельным запуском на тех же
  аргументах, сбой одного выхода не останавливает остальные, а по каждому выходу
  сообщается результат.
- Манифест пакетного режима — JSON-объект с двумя ключами: `common` — список
  аргументов, общий для всех выходов, включая источники сравнения и все
  параметры загрузки, — и `outputs`, непустой список записей
  `{"name": ..., "args": [...]}`. Каждый выход обязан назвать свой файл через
  `-o`, два выхода не могут совпадать по имени или писать в один файл, а в
  `args` выхода допустимы только параметры, действующие после загрузки
  (`--ignore-list`, `--allowed-object`, `--safe-mode`, `--pre-script`,
  `--post-script` и прочие флаги генерации скрипта); всё, что влияет на
  загрузку, задаётся в `common`. `--mode`, `--batch-manifest`, `--run-on`,
  `--run-on-target` и информационные параметры отклоняются в любой части
  манифеста.
- Пакетный запуск завершается ненулевым кодом, если не удался хотя бы один
  выход, при этом удавшиеся выходы всё равно записаны; строка итога по каждому
  выходу в потоке ошибок называет, какой именно не удался и почему.
- Добавлен явный параметр `--project-file-filter` с упорядоченными правилами
  включения и исключения SQL-файлов проекта относительно его корня.
- Добавлен явный параметр `--ignore-sequence-cache`: параметр `CACHE`
  последовательности не участвует в сравнении и не порождает `ALTER` — как для
  отдельной последовательности, так и для identity-последовательности столбца.
  Создаваемая миграцией последовательность по-прежнему создаётся с тем значением
  `CACHE`, которое записано в проекте.
- Добавлен явный параметр `--no-alter-table-only`: `ONLY` не выписывается ни в
  одном `ALTER TABLE`, который порождает миграция. `ONLY` не даёт изменению
  дойти до таблиц, наследующих названной, а гипертаблица TimescaleDB отвергает
  его для всех подкоманд кроме `SET` и `RESET` настроек, причём отвергает
  оператор целиком. Какие таблицы являются гипертаблицами, генератор знать не
  может: набор различается между базой, по которой снят скрипт, и базами, куда
  он применяется. Две формы, которые TimescaleDB разрешает, слово сохраняют.
- Добавлен явный параметр `--ignore-column-statistics`: statistics target
  колонки (`attstattarget`) не участвует в сравнении и не порождает `ALTER` —
  для базы, где эти значения ведёт собственное регулярное задание. Создаваемая
  миграцией колонка по-прежнему получает значение из проекта. Объекты
  `CREATE STATISTICS` не затрагиваются.
- Добавлен постоянный кэш каталогов PostgreSQL: `--pg-catalog-cache-dir` задаёт
  каталог хранения, `--pg-catalog-cache-max-mb` — предел его размера, благодаря
  чему повторное сравнение перестаёт скачивать неизменившиеся тела подпрограмм.
  Пока каталог не указан, ничего не пишется. Дополнительный параметр
  `--pg-catalog-cache-rows` распространяет то же хранилище на целые строки
  каталогов по серверному хэшу строки, так что прогретое сравнение передаёт
  только изменившиеся строки; без самого хранилища этот параметр отклоняется.
- Добавлен параметр `--jdbc-fetch-size` — число строк каталога, забираемых за
  одно обращение к базе. Ноль оставляет значение по умолчанию из драйвера, так
  что существующий вызов работает ровно как прежде.
- Добавлен переключатель отката для каждой части профиля загрузки, который CLI
  теперь включает по умолчанию: `--no-parallel-load`,
  `--pg-routine-body-no-hash-first`,
  `--pg-routine-body-no-skip-matched-analysis` и
  `--pg-parallel-catalog-readers 0`, а также
  `--pg-routine-body-residual-batch-count` и
  `--pg-routine-body-residual-batch-bytes` для размера пачки остаточных тел.
- `--parallel-load` (`-par`) и `--pg-routine-body-hash-first` идемпотентны: оба
  называют поведение, которое утилита применяет и без них, поэтому их передача
  ничего не меняет. Вызов, где `--parallel-load` уже указан, продолжает работать
  без правок; чтобы выбрать противоположное поведение, нужен парный
  `--no-parallel-load` или `--pg-routine-body-no-hash-first`.
- Добавлена запись в журнал перед началом загрузки: каталог кэша, предел его
  размера и признак кэширования строк. Запуск, потерявший настройку кэша, виден
  в журнале запуска `~/.pgcodekeeper-cli/logs/pgcodekeeper-cli.log`, а не только
  по времени работы.
- Добавлены системные свойства JVM для профиля памяти парсера:
  `-Dru.taximaxim.codekeeper.parser.maxpending` ограничивает число одновременно
  поставленных задач разбора, `-Dru.taximaxim.codekeeper.parser.maxpendingbytes` —
  ту же очередь по объёму исходников, а
  `-Dru.taximaxim.codekeeper.parser.bodycache.maxstates`,
  `-Dru.taximaxim.codekeeper.parser.bodycache.maxconfigs` и
  `-Dru.taximaxim.codekeeper.parser.bodycache.maxcontexts` ограничивают общий
  кэш предсказаний парсера. Это рычаг для запуска, который должен уложиться в
  кучу меньше той, что просит проект.

### Изменено

- Сравнение с базой PostgreSQL по умолчанию выполняется по оптимизированному
  профилю: обе стороны загружаются одновременно, размер выборки JDBC равен 512,
  тела подпрограмм сначала сопоставляются по хэшу и только потом дочитываются,
  остаточные тела читаются ограниченными пачками, а каталоги читают три
  дополнительных соединения на общем снимке. Значения по умолчанию Core и IDE не
  изменились, у каждой части профиля есть явный переключатель отката, а загрузка,
  которой не удалось разделить снимок, сама переходит к последовательному чтению.
- Одновременная загрузка обеих сторон сравнения и размер выборки JDBC 512 стали
  умолчанием для всех диалектов, а не только PostgreSQL: сравнение MS SQL или
  ClickHouse тоже открывает обе стороны сразу и забирает строки каталогов
  блоками по 512. `--no-parallel-load` выбирает последовательную загрузку,
  `--jdbc-fetch-size 0` — значение драйвера, и это работает на любом диалекте.
  Три дополнительных читателя каталогов и обмен телами по хэшу остаются только
  для PostgreSQL.
- Сравнение, выгрузка проекта и его обновление больше не строят индекс ссылок на
  объекты. Командная утилита его не читает — он существует для редактора, — и его
  построение тратило время и память на каждом запуске.
- Пакетный режим строит графы зависимостей загруженного сравнения один раз и
  переиспользует их для всех выходов, а не перестраивает под каждый скрипт.
- Запуск больше не читает метаданные авторства объектов, которые не нужны ни
  сравнению, ни выгрузке проекта: из каждой загрузки уходит соединение с ещё
  одним каталогом.
- Задачи разбора ставятся в очередь ограниченным окном — по умолчанию вдвое
  больше размера пула парсера, — а не все сразу, что снижает пик памяти на
  стадии разбора. Значение ноль или меньше в
  `-Dru.taximaxim.codekeeper.parser.maxpending` возвращает неограниченную
  постановку.
- Скрипты запуска определяют исполняемый файл Java и размер кучи двумя
  задокументированными порядками. Исполняемый файл: непустая `PGCK_JAVA_EXE`,
  затем `JAVA_HOME/bin/java`, затем `java` из `PATH` — на машине, где
  `JAVA_HOME` и `PATH` указывают на разные JDK, теперь берётся тот, который
  назван в `JAVA_HOME`. Куча: сначала значения, явно переданные после `-vmargs`,
  затем переменные окружения `PGCK_JAVA_XMS` и `PGCK_JAVA_XMX`, затем встроенные
  `-Xms256m -Xmx3072m`. Оба скрипта заключают путь к исполняемому файлу в
  кавычки и сохраняют метасимволы Windows и значения с пробелами по краям,
  поэтому путь с пробелом или амперсандом больше не ломает командный процессор;
  оба также дают JVM немедленно завершиться при нехватке кучи, а не продолжать
  работу с погибшими рабочими потоками.
- Сокращён объём данных каталога таблиц PostgreSQL: локальные для снимка метаданные
  типов и правил сортировки переиспользуются вместо повторной передачи метаданных
  каждой колонки.
- Постоянный кэш строк каталога PostgreSQL совмещён с параллельными читателями,
  использующими общий снимок, с сохранением канонического порядка результата.
- Упорядоченные хэши строк прогретого кэша упакованы в один компактный бинарный
  результат, что сокращает число строк результата, накладные расходы протокола и
  объём передаваемых по сети данных до загрузки изменённых строк.
- Добавлены пространства имён постоянного кэша для каждой целевой БД; размер
  сериализованной записи кэша строк каталога ограничен 32 МиБ, а неблокирующая
  очистка по лимиту после запуска усилена и выполняется в режиме best effort.
- Общие CLI-параметры постоянного кэша остались отключёнными по умолчанию и
  включаются только явно. Интеграционный bootstrap может передавать их только по
  собственной opt-in-политике, не меняя значения по умолчанию CLI или Core;
  три параллельных читателя каталогов остаются стандартным режимом CLI. Прогретый
  кэш строк предназначен прежде всего для сокращения сетевого трафика и числа
  обращений к серверу при повторных сравнениях, без гарантий снижения CPU/RSS
  или ускорения холодного запуска.

### Исправлено

- Скрипты запуска включают дедупликацию строк в JVM, поэтому поставляемая с ними
  куча теперь выдерживает загрузку большого проекта, а не заканчивается на ней.
  Пик приходится на загрузку: обе стороны сравнения одновременно держат текст
  каждого файла исходников, и на реальном проекте это в основном одна и та же
  строка дважды — на проекте в 24 тысячи файлов дубликатами оказались 96,7%
  строк, переживших молодую сборку мусора. Явный
  `-vmargs -XX:-UseStringDeduplication` по-прежнему имеет приоритет.
- Режим `--mode GRAPH` останавливается и сообщает об ошибках загрузки, а не
  печатает неполный граф зависимостей, завершаясь успешным кодом возврата и
  пустым потоком ошибок. Пайплайн, строивший работу по такому графу, не имел
  никакой возможности заметить, что читает неполные данные.
- Причина сбоя теперь печатается, а не подавляется всякий раз, когда вдобавок
  накопились ошибки разбора; непредвиденная ошибка в любом месте запуска
  сообщается вместе с причиной и ненулевым кодом возврата, а не голым стеком
  вызовов или вовсе ничем.
- Некорректный ignore-список — переданный явно, переданный как список схем или
  подхваченный из проекта — и некорректный файл зависимостей теперь останавливают
  весь запуск с сообщением, называющим файл и позицию первой ошибки, вместо того
  чтобы молча сравнить всё, что этот файл должен был исключить, или выписать
  скрипт в том порядке, который этот файл должен был исправить.
- Отклоняется токен, склеивающий имя параметра и его значение через пробел.
  Такой токен заставлял флаг без значения бесконечно крутить разбор аргументов на
  полной загрузке процессора, а параметр со значением проходил незамеченным —
  запуск мог отчитаться об успехе, загрузившись с выключенным постоянным кэшем.
- Параметр `--pg-parallel-catalog-readers` отклоняется при `--db-type MS` и
  `--db-type CH`, а его значение по умолчанию из профиля CLI больше не
  применяется к другим диалектам — как у всех остальных параметров `--pg-*`.
- Прекращена выписка `CREATE INDEX ... ON ONLY` для секционированной таблицы,
  индексов секций которой нет в модели. `ON ONLY` оставляет индекс невалидным,
  пока к нему не прикреплены индексы всех секций, а прикрепления выписываются
  только для тех секций, что есть в модели; когда их нет ни одной, индекс так и
  оставался невалидным и ни один план им не пользовался. Теперь слово
  выписывается только там, где прикрепления за ним следуют, поэтому проект,
  хранящий свои секции, не затронут.
- Исправлены порядок смены владельца последовательностей PostgreSQL,
  восстановление прав, использование нового имени после переименования и
  обязательная остановка при фильтрации смены владельца связанной таблицы.
  Последовательности, переживающие пересоздание связанной колонки или таблицы,
  теперь временно отвязываются и привязываются обратно без потери OID, текущего
  значения, свойств, владельца и прав.
- Анализ PostgreSQL защищён от неполных `SELECT`-деревьев после восстановления
  парсера; исправлены сигнатуры, псевдонимы и ordinality для `ROWS FROM` без
  явного псевдонима.
- Устранены ложные предупреждения парсера `regtype` для многословных, массивных
  и параметризованных имён типов с сохранением зависимостей квалифицированных
  пользовательских типов.

### Исправлено

- Исправлена генерация имен по умолчанию для объектов CONSTRAINT и SEQUENCE в PostgreSQL.
- Исправлена работа логики с нормализацией представлений для ClickHouse.

- Исправлено ложное различие для объекта STATISTICS в MS SQL.
