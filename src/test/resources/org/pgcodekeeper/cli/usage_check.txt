Usage
	pgcodekeeper-cli [option]... SOURCE DEST
	pgcodekeeper-cli -s SOURCE -t DEST [option]...
	pgcodekeeper-cli --mode PARSE -o OUTDIR [--update-project] [option]... SOURCE
	pgcodekeeper-cli --mode GRAPH [option]... SOURCE
	pgcodekeeper-cli --mode BATCH --batch-manifest MANIFEST

 SOURCE                                 : source of schema changes
 DEST                                   : destination for schema changes (diff
                                          mode only)
 --add-transaction (-X)                 : wrap generated script with
                                          transaction statements
 --additional-dependencies <path>       : add a file with a list of additional
                                          dependencies
 --allow-danger-ddl (-D)                : allows dangerous statements in
 <DANGER_STATEMENT>                       safe-mode scripts
 --allowed-object (-O) <OBJECT_TYPE>    : build the script using these object
                                          types only, hide statements of other
                                          objects
 --batch-manifest <path>                : path to a JSON batch manifest: shared
                                          load arguments plus several outputs
                                          generated from a single loaded
                                          comparison
                                          each output is byte-identical to a
                                          standalone run with common + output
                                          args
                                          failed outputs do not stop the others
                                          and are reported on stderr (BATCH
                                          mode only)
 --clear-lib-cache                      : clear library cache
 --cluster-name <name>                  : the name of the cluster that will be
                                          applied to all tables (experimentally,
                                          only for ClickHouse)
 --comments-to-end                      : print comments at the end of the
                                          script
 --concurrently-mode (-C)               : print CREATE INDEX with CONCURRENTLY
                                          option for PostgreSQL and WITH ONLINE
                                          = ON for MS SQL
 --db-type [PG | MS | CH]               : specify database type for work: PG,
                                          MS, CH (default: PG)
 --disable-auto-load                    : disable automatic loading of project
                                          auxiliary files
 --drop-before-create                   : print DROP before CREATE statement
 --enable-function-bodies-dependencies  : enable dependencies from bodies of
 (-f)                                     functions and procedures to other
                                          functions or procedures
 --error (-E)                           : print exception stacktrace
 --generate-constraint-not-valid (-v)   : print CONSTRAINT NOT VALID for no
                                          partitioned tables
 --generate-exist                       : print CREATE IF NOT EXISTS / DROP IF
                                          EXISTS
 --generate-exist-do-block (-do)        : print creation of CONSTRAINT and
                                          IDENTITY in DO block (PG only)
 --graph-depth <n>                      : depth of displayed dependencies in
                                          graph mode (default: 10)
 --graph-filter-object <OBJECT_TYPE>    : show these object types, hide other
                                          objects types
 --graph-invert-filter                  : invert graph filter object types:
                                          hide objects specified by the filter
 --graph-name <name>                    : name of start object in graph mode
                                          specify multiple times to use several
                                          names
 --graph-reverse                        : reverse the direction of the graph to
                                          show objects on which the starting
                                          object depends
 --help                                 : show this help
 --ignore-column-order                  : ignore differences in table column
                                          order
 --ignore-column-statistics             : ignore the statistics target of
                                          columns (attstattarget) when
                                          comparing; CREATE STATISTICS objects
                                          are unaffected
 --ignore-concurrent-modification (-m)  : ignore concurrent modification errors
                                          of database objects
 --ignore-errors                        : do not stop on parse errors
 --ignore-list (-I) <path>              : use an ignore list to include/exclude
                                          objects from diff
                                          specify multiple times to use several
                                          lists
 --ignore-schema <path>                 : use an ignore schema list to
                                          include/exclude schemas at loading
                                          stage
 --ignore-sequence-cache                : ignore the CACHE parameter of
                                          sequences when comparing
 --in-charset <charset>                 : input charset (default: UTF-8)
 --jdbc-fetch-size <n>                  : JDBC catalog fetch size; 0 keeps the
                                          driver default (default: 512)
 --keep-newlines (-L)                   : keep newline characters as is (don't
                                          convert to Unix newlines)
 --lib-safe-mode                        : exit with an error if a library
                                          object conflicts with other schema or
                                          library objects
                                          otherwise, in case of conflicts
                                          objects loaded first have priority
 --list-charsets                        : show list of Java-supported charsets
 --migrate-data                         : migrate data when re-creating tables
 --mode [DIFF | PARSE | GRAPH | BATCH]  : specify mode:
                                          DIFF - to compares the two sources
                                          and generates a migration script;
                                          PARSE - to save database schema as a
                                          directory hierarchy;
                                          GRAPH - to search for dependencies of
                                          an object;
                                          BATCH - to generate several migration
                                          scripts from one loaded comparison,
                                          see --batch-manifest;
                                           (default: DIFF)
 --no-alter-table-only                  : write ALTER TABLE without ONLY, so
                                          changes reach inheritance children
                                          and TimescaleDB hypertables accept
                                          them
 --no-check-function-bodies (-F)        : set check_function_bodies to false at
                                          the beginning of the script
 --no-parallel-load                     : load the comparison sides
                                          sequentially (rollback switch for the
                                          --parallel-load default); also turns
                                          the hash-first routine body default
                                          off
 --no-privileges (-P)                   : ignore privileges and owners of
                                          database objects
 --out-charset <charset>                : output charset (default: UTF-8)
 --output (-o) <path>                   : script output file or parser output
                                          directory
 --parallel-load (-par)                 : use parallel database loading
                                          (default; this flag is a no-op kept
                                          for script compatibility, see
                                          --no-parallel-load)
 --pg-catalog-cache-dir <path>          : persistent local cache directory for
                                          PostgreSQL routine bodies fetched on
                                          the hash-first path; repeat
                                          comparisons skip downloading
                                          unchanged bodies
 --pg-catalog-cache-max-mb <n>          : size cap of the PostgreSQL catalog
                                          cache in megabytes; oldest entries
                                          are pruned after a run (default: 512)
 --pg-catalog-cache-rows                : additionally cache whole PostgreSQL
                                          catalog reader rows keyed by a
                                          server-side row hash; repeat
                                          comparisons transfer only changed rows
 --pg-parallel-catalog-readers <n>      : read PostgreSQL catalogs with N extra
                                          connections sharing the primary
                                          snapshot; 0 keeps the sequential
                                          flow; loads that cannot share the
                                          snapshot fall back to sequential
                                          reading (CLI default: 3; the core/IDE
                                          default stays 0)
 --pg-routine-body-hash-first           : reuse matching PostgreSQL routine
                                          bodies from the project and fetch
                                          only residual bodies (default for
                                          PostgreSQL DIFF mode; this flag is a
                                          no-op kept for script compatibility,
                                          see --pg-routine-body-no-hash-first)
 --pg-routine-body-no-hash-first        : always fetch full PostgreSQL routine
                                          bodies from the database (rollback
                                          switch for the hash-first default);
                                          cannot be combined with the
                                          hash-first-only options
                                          --pg-routine-body-residual-batch-count
                                          , --pg-routine-body-residual-batch-byt
                                          es and --pg-catalog-cache-dir
 --pg-routine-body-no-skip-matched-anal : always analyze and fetch database
 ysis                                     routine bodies (rollback switch); by
                                          default late-bound bodies (plpgsql,
                                          or quoted sql with --no-check-function
                                          -bodies) skip dependency analysis on
                                          the hash-first path: bodies
                                          byte-identical between project and
                                          database skip on both sides, and
                                          every eligible body of the database
                                          acting as the old comparison side
                                          skips regardless of the match, with
                                          unmatched old-side bodies not even
                                          fetched; such functions lose
                                          collateral recreates in drop
                                          cascades; changed project bodies are
                                          always analyzed
 --pg-routine-body-residual-batch-bytes : predicted UTF-8 grouping budget for
 <n>                                      each PostgreSQL residual routine body
                                          batch; one oversized body is fetched
                                          alone (default: 33554432)
 --pg-routine-body-residual-batch-count : maximum PostgreSQL residual routine
 <n>                                      bodies per JDBC batch (default: 256)
 --post-script <path>                   : POST script file path or directory
                                          with POST scripts
                                          nested directories are loaded
                                          recursively
                                          specify multiple times to use several
                                          paths
 --pre-script <path>                    : PRE script file path or directory
                                          with PRE scripts
                                          nested directories are loaded
                                          recursively
                                          specify multiple times to use several
                                          paths
 --project-file-filter <path>           : filter top-level project files using
                                          ordered rules from a UTF-8 file
                                          (opt-in)
 --run-on (-R) <JDBC>                   : run generated script on the specified
                                          database
 --run-on-target (-r)                   : run generated script on the target
                                          database
 --safe-mode (-S)                       : do not generate scripts containing
                                          dangerous statements
                                          see: --allow-danger-ddl
 --selected-only                        : build the script using 'selected'
                                          objects only, hide statements of
                                          other objects
                                          in CLI, selected means included by
                                          --allowed-object and ignore lists
 --simplify-not-null                    : simplified reading of NOT NULL
                                          constraints via JDBC (only for
                                          PostgreSQL 18+)
 --simplify-views                       : simple formatting for VIEWs when
                                          reading via JDBC (not recomended by
                                          PostgreSQL)
 --source (-s) <path or JDBC>           : source of schema changes
 --src-lib <path or JDBC>               : add library to source
                                          specify multiple times to use several
                                          libraries
 --src-lib-no-priv <path or JDBC>       : add library to source without
                                          privileges
                                          specify multiple times to use several
                                          libraries
 --src-lib-xml <path>                   : add xml with libraries to source
                                          specify multiple times to use several
                                          libraries xml's
 --stop-not-allowed                     : exit with an error when
                                          --allowed-object hides a dependency
                                          statement from the script
 --structure-file <path>                : path to a properties file with
                                          directory layout overrides for parse
                                          mode
 --target (-t) <path or JDBC>           : destination for schema changes (diff
                                          mode only)
 --tgt-lib <path or JDBC>               : add library to destination
                                          specify multiple times to use several
                                          libraries
 --tgt-lib-no-priv <path or JDBC>       : add library to destination without
                                          privileges
                                          specify multiple times to use several
                                          libraries
 --tgt-lib-xml <path>                   : add xml with libraries to target
                                          specify multiple times to use several
                                          libraries xml's
 --time-zone (-Z) <timezone>            : use this timezone when working with
                                          database, also add SET TIMEZONE
                                          statement to the script
 --update-project                       : update an existing project in parse
                                          mode
 --use-actual-syntax                    : use the current syntax to generate
                                          the migration script (currently not
                                          implemented)
 --using-off                            : do not print USING expression for
                                          ALTER COLUMN TYPE
 --version                              : show version

DANGER_STATEMENT : [DROP_TABLE | ALTER_COLUMN | DROP_COLUMN | RESTART_WITH | UPDATE]
OBJECT_TYPE : [CAST | USER | ROLE | ASSEMBLY | SCHEMA | EXTENSION | EVENT_TRIGGER | FOREIGN_DATA_WRAPPER | SERVER | USER_MAPPING | COLLATION | TYPE | DOMAIN | SEQUENCE | OPERATOR | FTS_PARSER | FTS_TEMPLATE | FTS_DICTIONARY | FTS_CONFIGURATION | TABLE | DICTIONARY | FUNCTION | PROCEDURE | AGGREGATE | INDEX | CONSTRAINT | VIEW | STATISTICS | TRIGGER | RULE | POLICY]

Library load order
	Libraries are loaded in the following order:
		1. Libraries in specified XML lists.
		2. Explicitly specified libraries.
		3. Explicitly specified libraries without privileges.
	In each group order is defined by the given argument order. Within XMLs entry order is used.
	Objects loaded first in this sequence may override ones loaded later (if --lib-safe-mode is off).

Live database connections
	Use JDBC connection URL to specify live databases
		PostgreSQL: https://jdbc.postgresql.org/documentation/head/connect.html
		MS SQL: https://docs.microsoft.com/sql/connect/jdbc/building-the-connection-url
		ClickHouse: https://clickhouse.com/docs/en/integrations/java#configuration
